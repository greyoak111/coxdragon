## 2026-11-16：vivo 日志与 CodeFlow 上游错误

- 用户提供的 vivo V2456A / Android 16 诊断包未包含崩溃堆栈；随后界面报错明确为 CodeFlow 的 `upstream_error`。原诊断包没有任务错误与完成状态，不能仅由包内的模型元数据警告判断任务是否完成。
- DeepSeek 模型的协议自动识别优先 Chat Completions，显式选择仍保持优先；Responses 连通测试加入结构化输入和工具上下文，空完成事件、仅思考和截断回复不再算通过。连通测试仍不等价于完整编码任务验收。
- 对 CodeFlow Responses 上游错误显示一次可读错误及 Request ID，并提供保留已保存密钥的 Chat 切换按钮；不会自动重放任务。重开历史时也呈现任务错误，延迟的线程状态不再叠加相同错误卡。
- Chat 适配器转发服务端实际返回的 `reasoning_content` / `reasoning` 文本，保持思考、回复与工具各自的输出索引；空回复明确失败。自定义连接限制请求和流式重试次数，并设置 90 秒流空闲超时。
- 任务开始、失败、重试和结束写入有界诊断快照及网关日志，原生日志包包含该快照；不保存提示、回复或工具参数，错误文本脱敏。未安装的可选 Claude 不再导致自检和状态对账报红。
- GitHub 发布列表核实：`v0.1.4` 只提供 `coxdragon-0.1.4-mcp-input.apk`，没有更新器约定的标准 APK。更新检查跳过不包含当前 targetSdk 标准文件的发布，不猜测安装另名测试包。
- 37 项协议/连接回归和手机、平板、桌面中英文浏览器回归通过；固定 `0.166.0` 真实引擎配合本地合成接口完成思考文本、回复及工具往返。本轮未重复调用真实服务商，未在日志来源 vivo 设备上验收。
