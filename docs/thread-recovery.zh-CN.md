# 空任务持久化与记录缺失恢复（26.1.6）

2026-11-17 的 vivo V2456A / Android 16 诊断中，多次发送失败均发生在 `thread/resume`：`no rollout found for thread id …`。没有对应的 Android 崩溃或 ANR 堆栈。只读检查未找到失败任务对应的本地 rollout；日志中的 GitHub 更新检查网络错误是另一个问题。

## 根因和修复

固定 Codex app-server 0.166.0 的 `thread/start` 可以先返回任务 ID 和路径，尚未将空任务写入磁盘。首次发送前重启引擎，再恢复这个 ID，就会出现上述错误。单纯等待或设置 `ephemeral: false` 不足以确认空任务已经持久化。

创建任务时显式设置 `ephemeral: false`，随后调用此版本支持的 `thread/name/set` 写入占位名称，确认成功后才切换当前任务。占位名称在列表中让位给首条消息的预览。此过程不请求模型，也不伪造对话。写入失败保留原任务视图。

对于已经缺失记录的任务：

- 冷启动会核验已保存的任务 ID，即使它不在列表第一页。
- 精确识别引擎的记录缺失错误，返回 `thread_history_missing`，显示“重试恢复”和“新建任务并保留草稿”。其他传输或服务商错误保留原处理方式。
- 选择新建后保留原草稿，并复制到新任务，包括引用和请求期间继续输入的内容；创建失败不切换任务。不会自动发送，需要用户确认草稿后发送。
- 新任务不会包含已经缺失的旧聊天历史。修复能防止新空任务出现同类丢失，也能解除旧失效 ID 对发送的阻塞；不能凭空恢复缺失文件。
- 恢复失败写入现有私有诊断快照；不新增记录提示词、回复、工具参数或密钥。

兼容依据是固定 `rust-v0.166.0` 源码、JSON schema 和真实进程验证。官方文档网页在本机网络返回 403，因此未将网页最新内容作为已核验依据。

- `node scripts/test-codex-process.mjs`：真实 0.166.0 进程验证新空任务写盘及引擎重启后恢复。在隔离测试目录临时移走 rollout 可复现原错误，且不会调用模型。其余权限、配置、上下文和工具回归也通过；服务商为合成接口，无真实模型请求。
