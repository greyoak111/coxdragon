# Codex Desktop 工作流复刻

目标是在现有 Android 应用里逐步实现桌面工作台的工作流，继续使用官方
`codex-app-server`、本机鉴权网关和 Android 应用沙箱。手机使用抽屉和全屏面板，
平板使用并排布局；功能以真实接口和真机验收为准。

参考官方文档：[项目与聊天](https://learn.chatgpt.com/docs/projects)、
[代码审阅](https://learn.chatgpt.com/docs/code-review)、
[集成终端](https://learn.chatgpt.com/docs/integrated-terminal)。这是独立客户端，
不是 OpenAI 官方应用，也不声称与官方桌面版逐像素一致。

## 阶段一：本地任务闭环

- 项目分组、线程搜索、固定线程、新建任务、按线程保存输入草稿。
- 项目目录贯穿任务、文件浏览、终端和 Git 面板。
- 任务执行、停止、流式消息、计划、命令和文件改动卡片。
- 切换线程时按 threadId 隔离事件，停止和发送显式指定目标线程。
- 重连补发待审批请求；引擎退出后清理失效审批。
- 工作台内查看 Git 改动清单、逐行 diff，再进入现有 Git 面板提交。
- 宽屏并排工作台和窄屏抽屉；中文和英文界面。
- 安卓默认进入 Codex；返回键先关闭项目选择、侧栏或审阅面板。

验收：在项目 A 发起任务，切到 B 后 A 的消息不进入 B；返回 A 能查看记录和
停止 A；离开页面期间产生的审批在回来后可处理；审阅、终端和文件操作使用
当前项目目录。浏览器隔离测试用于交互回归，APK 和 Android WebView 仍需真机验证。

回归命令：`node scripts/test-codex-engine.mjs`（Windows / Linux / Android），
`node scripts/test-codex-ui.mjs`（需要 Chromium，可用 `CHROMIUM_BIN` 指定路径）。
添加 `--screenshots` 将界面截图保存到 `.cache/codex-workflow/`。浏览器测试使用
内存项目和协议替身，不连接账号、不启动真实模型或项目工具。

首版的固定线程和草稿保存在当前 WebView 的本地存储；项目清单复用现有网关。
改动面板展示整个项目工作区的 Git diff，尚未按任务归因。新增导航支持中文和
英文，其他语言暂用英文；原有执行与审批卡片仍有未翻译文案。

## 已补齐：设置、后台通知与扩展入口

- 工作台使用独立的 Codex 设置：真实账号状态、账号返回的模型及支持的思考强度。
  模型偏好原子保存到应用 home 下的 `coxdragon-codex.json`，下一次发送时交给
  `turn/start`；写入失败时不更新已生效的选择。这是本客户端的全局偏好，不会覆盖
  `config.toml`，也还没有按线程保存。
- 权限区显示实际固定策略 `untrusted` 与 `danger-full-access`，说明安卓应用身份
  的访问范围；没有将旧引擎的权限开关伪装为 Codex 设置。
- Codex 初始化等待、待回执、运行和待确认请求均计入 `.run-active`；旧引擎排队与
  Codex 分别持有忙碌标记。关闭一个引擎不会清掉另一个引擎的任务标记。
  `/api/status`、主事件总线和重连快照包含 Codex 状态。
- 安卓服务收到 Codex 完成、失败、待确认事件后使用现有通知渠道；通知中拒绝会
  调用 Codex 审批接口，打开通知会回到对应 Codex 线程。任务中断不发完成通知。
- 「技能与 MCP」通过 `skills/list`、`skills/config/write` 和
  `mcpServerStatus/list` 工作，展示当前项目发现的技能、技能开关、MCP 认证状态
  与工具数量，并提供 `AGENTS.md` 和 `config.toml` 所在目录的文件入口。
  MCP 最多展示 100 个服务；单个接口报错不会把另一类扩展隐藏。

协议依据：[官方 App Server 文档](https://developers.openai.com/codex/app-server/)。
插件市场的安装、MCP 认证/编辑向导、可配置权限档案及旧引擎设置的全面迁移仍未完成。
自动化测试使用协议替身；系统通知送达、冷启动与 Android 后台限制仍需真机验收。

工作台外的分享、更新、后台维护、调度、用量和恢复入口的检查与修复情况，
见 [Codex 集成检查](codex-integration-audit.zh-CN.md)。

## 模型连接可选

引导提供 ChatGPT 登录、自定义第三方 API 和跳过三个入口，并在原生引导和网页
明确标注这是独立客户端，非 OpenAI 官方应用。跳过会保留在当前 WebView 中，
可以先浏览工作台、管理项目；发送任务时再配置连接，输入草稿会保留。

自定义 API 需要填写基础地址（如 `https://example.com/v1`）、模型名和密钥，
支持 OpenAI Responses、OpenAI Chat Completions 和测试后自动识别协议。
可粘贴完整的 `/responses`、`/chat/completions` 或 `/models` 地址，客户端会规范化为
基础地址。填写地址和密钥后自动获取模型，也提供手动获取、按名称筛选与手动输入。
未实现模型目录的服务仍可手填。无需认证的本地接口可明确选择不使用 API Key。

对于网站根地址，检测先尝试同源 `/v1` 路径，再检查原路径；不会猜测其他域名或
跟随重定向转发密钥。返回网页会明确提示使用服务商的 API 地址，不展示 HTML。
测试连接会发送最多 32 输出 token 的短请求，可能产生少量费用；结果包括协议、
实际请求地址、HTTP 状态、耗时及失败原因。自动协议识别只在路径或协议不匹配时
尝试下一种协议，鉴权、额度和网络失败不重复发起模型请求。

连接信息保存在应用私有 home 的 `coxdragon-codex-connection.json`，模式为 0600。
状态回执仅返回密钥是否存在；密钥不会进入启动参数或前端本地存储，启动引擎时
通过环境变量交给 Responses provider。更换地址需要重新填写密钥，避免把旧密钥误发到
新地址。通过 CLI 配置覆盖选择 provider，不改写用户 `config.toml`。

保存连接不会试发模型请求；有任务、初始化或审批在等待时拒绝切换，保存失败会
保留原连接。切换后重启 Codex 子进程，新建与恢复线程都使用所选 provider。
自定义模型按用户填写的模型名显示，不用 ChatGPT 的模型目录替代第三方能力。

Codex 原生只支持 Responses；Chat Completions 通过仅监听 `127.0.0.1` 的本地
适配器转换文本、图片、函数调用、自定义文本工具和工具输出。引擎只获得随机回环
令牌，第三方密钥保留在网关内存中。适配器不支持 Responses 专属内建工具、压缩
记录或以 previous_response_id 代替完整历史；遇到这些类型会明确报错。
连通性测试不等于完整工具能力测试。修改表单会使原测试结果失效，延迟检测结果
不能覆盖新输入；关闭页面取消未完成检测。检测不会保存设置或切换当前连接。

2026-11-15 验证：31 项引擎与连接回归测试、四种尺寸的中英文浏览器测试通过。
固定版本 `codex-app-server 0.166.0` 已与本机模拟 Responses 服务完成真实进程的
连接、认证头、模型选择与流式回包验证；Chat Completions 适配器另通过真实引擎的
命令工具调用、执行结果回传和后续流式回答闭环。没有调用真实模型。
两个签名 APK 已重新构建。Android 16 真机验证了模型获取和网页 404 错误提示；
更换的 Android 13 真机完成原生首次安装、工作环境下载及 WebView 启动，并验证了
模型获取、自动识别 Chat Completions、短请求测试成功，以及完整 Responses 地址的
规范化和测试成功。上述真机 API 测试连接电脑回环模拟服务，没有使用真实凭据。
真实账号／第三方模型调用、手机上的 Codex 任务执行及 targetSdk 36 仍需另行验收。

## 阶段二：持久化线程管理与执行控制

- 通过固定版本 app-server 的协议实现重命名、归档、恢复及分页搜索。
- 持久化每个线程的模型、思考强度和项目偏好，处理多客户端同时操作。
- 排队、运行中追加指令、并行任务状态与进程重启后的恢复。
- 文件／图片上下文、上下文用量、计划模式和权限配置。

## 阶段三：隔离开发与交付

- Git worktree 创建、切换、清理与每线程终端。
- 按任务审阅改动、行内反馈、暂存、提交和分支交付。
- 项目环境初始化和可重复执行的验证动作。

## 阶段四：扩展工作流与发布验收

- Codex 配置、AGENTS.md、技能、MCP 与插件的统一管理。
- 根据 app-server 和 Android 支持情况评估长期任务、通知和自动化。
- 在完整任务、审批、断网、进程被杀、旋转、软键盘和 targetSdk 36 场景下验收。

云端任务、官方账号侧服务、系统级浏览器／计算机控制等能力分别评估，不能用
前端按钮代替实际协议和 Android 支持。
